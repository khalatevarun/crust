# Remote access via Tailscale Serve, with a uniform device token on every request

Researched how comparable self-hosted single-user tools (Home Assistant, Plex, Portainer, Syncthing) solve "reach my server from my phone off my home network," and how comparable AI-agent products (Claude Code, Cursor, GitHub Copilot coding agent) shape their mobile companion experience. Two decisions follow from that:

**Network exposure: Tailscale Serve, not a built-in tunnel/relay.** crust doesn't manage tunneling, port-forwarding, or a hosted relay — the user runs `tailscale serve` themselves, which publishes the backend to their private tailnet at a stable `*.ts.net` HTTPS address with an auto-issued cert. This is the pattern home-lab/self-hosted communities converge on for a single operator with one or two devices; building our own relay (Nabu-Casa/Plex-Relay-style) or defaulting to Funnel/Cloudflare Tunnel/ngrok would mean either standing up real infrastructure or exposing the backend publicly, neither justified at this scale.

**Auth: every request needs a Device Token, including the desktop browser.** Tailscale Serve forwards tailnet traffic to the app on `localhost` — a request proxied in from a phone over the tailnet and a request from the desktop browser on the same machine both arrive indistinguishable by IP. Rather than depend on Tailscale's proxy behavior (headers, or version-specific forwarding semantics) to tell them apart, every request — local or remote — is authenticated the same way. This is simpler to reason about, doesn't silently break if Tailscale's proxying behavior changes, and costs little: the desktop browser self-pairs on first run exactly like a phone would.

**Tokens don't expire; revocation is the only lifecycle event.** Matches Home Assistant's long-lived-access-token model. Time-boxing tokens defends against a threat this design doesn't have (an untrusted pairing channel, no revocation path) — pairing happens over an already-authenticated tailnet, and a `devices` table with per-row deletion handles "I lost my phone" directly, which is the actual threat.

Considered and rejected: OAuth 2.0 Device Authorization Grant (the flow's roles are inverted for a headless-server-and-capable-phone setup, and it solves multi-client delegated consent, a problem a single-user tool doesn't have); a bare shared secret in an env var (no per-device identity, no revocation without rotating everywhere); trusting `127.0.0.1` as an implicit "local, no auth needed" signal (defeated by Tailscale Serve's local-proxy model, as above).
